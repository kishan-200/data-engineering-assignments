# ML & GenAI Enterprise Labs — 10 Problem Statements

This repository provides **fast, runnable educational baselines** for the 10 problem statements in the supplied lab handbook. It is designed for a short deadline and runs on Google Colab or a local Python environment.

## Important scope note
These are compact demonstrations, not production systems. P1–P3 demonstrate model training/evaluation; P4 demonstrates structured ticket routing with a deterministic fallback; P5–P6 demonstrate retrieval baselines; P7–P8 demonstrate controlled tool/agent workflows; P9 includes a QLoRA preparation/configuration scaffold (actual fine-tuning requires a suitable GPU, model access, and additional packages); P10 integrates a small RAG workflow, guardrails, and lightweight evaluation. Any API/model-dependent steps are optional and are not falsely reported as completed.

## Run in Google Colab
1. Upload this ZIP to Google Drive and extract it, **or** upload the ZIP directly into a Colab session and unzip it.
2. In a Colab cell:
   ```python
   !unzip -o ml_genai_enterprise_labs.zip
   %cd ml_genai_enterprise_labs
   !pip install -r requirements.txt
   !python run_all.py
   ```
   If the extracted folder name differs, adjust `%cd` accordingly.
3. The scripts write outputs under `results/`.

## Run locally
```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

```

## Problem mapping
| # | Script | Demonstration |
|---|---|---|
| P1 | `p1_iot_anomaly.py` | Linear regression RUL estimate, logistic failure risk, MAE/RMSE/recall |
| P2 | `p2_fraud_segmentation.py` | Decision Tree vs Random Forest, ROC-AUC, K-Means, silhouette score |
| P3 | `p3_demand_forecasting.py` | MLP regression, holdout metrics, loss curve |
| P4 | `p4_support_intent_router.py` | Ticket intent/priority routing, JSON schema-style output, prompt variant comparison |
| P5 | `p5_basic_healthcare_rag.py` | Text chunking, TF-IDF retrieval baseline, chunking comparison |
| P6 | `p6_hybrid_legal_rag.py` | Lexical + vector-style TF-IDF retrieval, reciprocal-rank fusion, reranking baseline |
| P7 | `p7_financial_analyst_agent.py` | SQL-like data lookup, document lookup, calculator tool, trace log |
| P8 | `p8_multi_agent_devsecops.py` | Security scanner, remediation suggestions, QA validation loop |
| P9 | `p9_qlora_claims_scaffold.py` | JSONL training-data preparation and optional QLoRA configuration notes |
| P10 | `p10_agentic_rag_capstone.py` | Retrieval + tools, basic input/output guardrails, small evaluation scorecard |

The examples use synthetic, non-sensitive sample data. Metrics are generated by executing the scripts and are not hard-coded claims. Some metrics may vary slightly across library versions. Review outputs before submitting.

## Additional assignment evidence
After running `python run_all.py`, the launcher also runs `src/generate_assignment_evidence.py` to create extra plots, CSV comparison tables, and scorecards under `results/` and `results/figures/`.

Examples include P1 actual-vs-predicted RUL and threshold-recall plots; P2 ROC, Elbow, cluster plots and model comparison CSV; P3 training/validation curve and model comparison; P4 prompt benchmark proxy; P5 chunking/retrieval comparison; P6 hybrid ranking and precision/recall proxy; P7 trace table; P8 audit table; P9 explicit fine-tuning status; and P10 capstone scorecard and architecture diagram.

**Honest evaluation note:** P4's benchmark is a rule-based proxy, P5/P6 use TF-IDF baselines, P7/P8 are controlled demonstrations, and P9 does not claim actual QLoRA training. P10 does not claim RAGAS metrics unless an actual evaluator is run. These files must not be described as production-grade or as full evaluations where the underlying model was not run.
